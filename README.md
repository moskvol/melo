# Melo

Веб-мессенджер на React, TypeScript, Vite и Supabase. Интерфейс построен в стиле Material 3 Expressive: адаптивные панели, светлая и тёмная темы, акцентные палитры, Material Symbols Rounded и анимации Motion.

## Возможности

- Регистрация по email с подтверждением, вход, восстановление пароля, сохранение сеанса и удаление аккаунта.
- Профиль, аватар, уникальный username, поиск людей и настройки приватности.
- Личные и групповые чаты, приглашения по ссылке, администраторы, права на отправку и блокировка.
- Текст, ответы, пересылка, редактирование, удаление, реакции, закрепление, вложения до 25 МБ, голосовые сообщения, черновики, поиск по открытой переписке, индикатор набора, счётчик непрочитанных и отметки прочтения.
- Supabase Realtime синхронизирует изменения на открытых клиентах. PWA кеширует только файлы интерфейса, не переписку. Уведомления браузера работают, пока Melo открыт; фоновые push-уведомления требуют отдельного сервера и здесь не включены.

Сквозного шифрования нет. Сообщения доступны участникам чата и серверу Supabase.

## Быстрый старт

1. Создайте новый проект в [Supabase](https://supabase.com/dashboard).
2. В **SQL Editor** выполните SQL-файлы из [`supabase/migrations/`](supabase/migrations/) по порядку. Нужен отдельный новый проект: миграции создают таблицы, политики RLS, триггеры, индексы и два Storage bucket.
3. В **Authentication → Providers → Email** включите подтверждение email. Настройте SMTP для реальной доставки писем (встроенный отправитель Supabase предназначен для ограниченного тестирования).
4. В **Authentication → URL Configuration** укажите Site URL (`http://localhost:5173/` локально) и добавьте Redirect URLs для локального адреса и GitHub Pages (`https://OWNER.github.io/REPO/`). Для восстановления пароля ссылка должна вернуться на тот же адрес.
5. Для входа по коду откройте **Authentication → Email Templates → Magic Link** и замените содержимое письма на шаблон с `{{ .Token }}`. Например:

   ```html
   <h2>Код входа в Melo</h2>
   <p>Введите этот шестизначный код в Melo: <strong>{{ .Token }}</strong></p>
   <p>Если вы не запрашивали код, проигнорируйте письмо.</p>
   ```

   Supabase отправляет ссылку по умолчанию; без изменения шаблона экран ввода кода не сможет получить код из письма. Вход по коду доступен существующим пользователям и не создаёт аккаунт.
6. Из **Project Settings → API Keys** возьмите Project URL и **publishable key** (`sb_publishable_...`). Никогда не вставляйте secret или `service_role` key в приложение.
7. Скопируйте `.env.example` в `.env.local` и заполните `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`.
8. Запустите команды:

   ```bash
   npm ci
   npm run dev
   ```

Откройте `http://localhost:5173/`. Для проверки сборки: `npm run build`. В сборке автоматически запускается TypeScript.

### Настройка Realtime

Миграция добавляет `messages`, `conversation_members` и `conversations` в публикацию `supabase_realtime`. Изменение реакций вызывает безопасное обновление связанного сообщения. Если проект уже менялся вручную, проверьте эти таблицы в **Database → Publications**. Для приватного индикатора набора выключите **Realtime → Settings → Allow public access**: миграция создаёт политики для каналов `typing-{chat_id}` и `changes-{user_id}`. Эти каналы используют `private: true`.

### Проверка двух аккаунтов

1. Зарегистрируйте аккаунт A, подтвердите письмо и войдите.
2. В другом профиле браузера зарегистрируйте аккаунт B и подтвердите письмо.
3. В A найдите `@username` B, откройте чат и отправьте сообщение. В B проверьте появление чата и сообщения без перезагрузки.
4. Ответьте из B, проверьте отметку прочтения после открытия чата в A.
5. Загрузите аватар в профиле A и файл в чат. Убедитесь, что B видит аватар и может открыть файл, а аккаунт C без членства не может читать сообщения или получить подписанный URL файла.
6. Откройте A в ещё одной вкладке и проверьте синхронизацию сообщений и реакций.

Эта проверка требует проекта Supabase и двух подтверждённых аккаунтов; без URL и publishable key локальная сборка показывает экран подключения.

## GitHub Pages

1. Создайте GitHub-репозиторий и отправьте код в ветку `main` или `master`.
2. В **Settings → Secrets and variables → Actions → Variables** добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Это публичные клиентские значения, поэтому используются Variables. Секретный серверный ключ не добавляйте.
3. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
4. В настройках Supabase добавьте `https://OWNER.github.io/REPO/` в Site URL / Redirect URLs.
5. Workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) запускает `npm ci`, сборку и публикацию. `VITE_BASE_PATH` вычисляется из имени репозитория. Приложение не использует серверные маршруты и совместимо с Pages.

Для репозитория вида `OWNER.github.io` (публикация в корне домена) измените `VITE_BASE_PATH` на `/` в workflow.

Встроенная отправка Supabase имеет строгие лимиты; во время проверки сервер вернул `email rate limit exceeded`.

## Безопасность и ограничения

- Политики RLS проверяют членство в чатах и полномочия администраторов на стороне PostgreSQL. Клиентский код не содержит привилегированных ключей.
- Сообщения ограничены 4096 символами и частотой не чаще одного в секунду на пользователя. Аватары ограничены 5 МБ и изображениями; вложения — 25 МБ. Ввод отображается React как текст, без небезопасного HTML.
- Вложения хранятся в закрытом bucket и открываются через краткосрочные подписанные URL. Аватары публичны.
- Черновики сохраняются в `sessionStorage` конкретного браузера и очищаются после отправки. Сервисный работник кеширует только оболочку приложения.
- Прочтение фиксируется при открытом чате; отметка доставки означает запись в серверную базу. Статус активности основан на времени последнего посещения при открытом приложении.
- Полноценные фоновые push-уведомления, управление отдельными активными сеансами и автоматическое удаление файлов из Storage при удалении аккаунта требуют дополнительной серверной инфраструктуры. Здесь доступны уведомления браузера при открытой вкладке и выход из текущего сеанса.
- Поиск сообщений выполняется среди последних 200 загруженных сообщений открытого чата. Список чатов загружает до 1000 последних сообщений для превью и счётчиков. Для крупных архивов потребуется серверная пагинация и агрегированные счётчики.

## Структура

- `src/App.tsx` — экраны, взаимодействия и Realtime.
- `src/lib.ts` — клиент Supabase и запросы.
- `src/styles.css` — адаптивные Material токены и компоненты.
- `supabase/migrations/` — схема, триггеры, RLS и Storage.
- `public/` — логотип, favicon и PWA-иконки.
